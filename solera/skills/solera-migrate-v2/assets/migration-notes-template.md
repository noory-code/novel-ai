## Manual Tasks (What You Should Do Next)

1. **If `team-process.md` was not migrated** (v2 project had none): run `solera-init` against this same directory — it will detect v4 presence and offer to run only the Kickoff Interview step to populate `team-process.md`. Without this, `workflow_gates` cannot be enforced.
2. Review Stories listed in **Stories Needing `contributes_to` Review** above.
3. Open each migrated Concept and fill in `# Horizon` and `# Health` — the migration drafts those as `(not set yet)` and `(no signals yet)`.
4. Open each migrated Concept and **refine the Intent**. The migration drafted Intent from v2 sources; treat those as starting points, not final. Intent is meant to be a long-lived north star — invest a minute on each.
5. **Re-home v3 catalog `persona/` and `journey/` artifacts to first-class Living-axis files**. These were parked in `.solera/catalog/published/_unclassified/persona-from-v3-catalog/` and `_unclassified/journey-from-v3-catalog/` by the migration. Run `solera-write-persona` and `solera-write-journey` for each artifact to formalize them — the skills require human-approved content (Identity / Goals / Steps / Outcome) that catalog files don't carry.
6. **Author Narratives (new in v4)** — there is no v2 source for Narratives. Run `solera-write-narrative` to capture "As a [Persona] I want [goal] so that [benefit]" statements and propose Concepts from them. The Service canvas exposes a "Propose as Concept" action that creates stub Concepts with human-review-required Intent.
7. Run `solera-write-milestone` to agree on the **first post-v4 Milestone scope**. The `pre-v3` milestone is just a historical frame; your first real v4 work starts with a new Milestone.
8. Delete `.solera/_v2-archive/` when you are confident nothing more is needed there (`git rm -r .solera/_v2-archive/` then commit).
